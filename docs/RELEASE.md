# Выпуск обновлений

Приложение получает обновления из `Strokln/Stroka`. Основной источник — файл `update.json` последнего GitHub Release. Резервные источники — `update/latest.json` в ветке main и его копии на jsDelivr.

## Подготовка

1. Увеличить `versionCode` и изменить `versionName` в `app/build.gradle.kts`.
2. Запустить workflow **Build Android from source**. Он собирает приложение и движок, проверяет ресурсы и конфигурацию обновлений и сохраняет APK в артефакте `dsh-android-build`.
3. Подписать APK прежним ключом. Без явно заданных параметров подписи Gradle использует отладочный ключ; такой APK нельзя публиковать как обновление. Ключ выпуска хранится локально и не должен попадать в репозиторий или артефакты сборки.
4. Проверить подписи v1/v2/v3 и выравнивание APK через Android SDK `apksigner` и `zipalign`.

## Манифест

Подготовить `notes-ru.md` и `notes-en.md`, затем сгенерировать манифест из окончательного подписанного APK:

```bash
python3 tools/make-update-manifest.py DSH-0.3.8-ru.1.apk \
  --notes-ru notes-ru.md --notes-en notes-en.md \
  --expect-signer a36e75295012cd85eac06a1a2fdfc7b224d579f394ffbd91ed8b5973a87bc269 \
  -o update.json
```

Версия, код версии, пакет, minSdk, размер, контрольная сумма и сертификат считываются из APK. По умолчанию ссылка ведёт на APK в `Strokln/Stroka` с тегом `v<versionName>`. Параметр `--repo` позволяет явно указать репозиторий. `--url` добавляет дополнительные HTTPS-адреса, `--tag` задаёт тег.

Требуются Android SDK `apksigner` и `aapt2`. Их можно передать через `--apksigner` и `--aapt2`; для Java следует задать `JAVA_HOME`.

## Публикация

1. Создать обычный Release, приложив APK, SHA-256 и манифест **с именем `update.json`**. Предварительные выпуски не должны становиться источником автообновлений.
2. Убедиться, что все файлы релиза доступны.
3. Только после публикации скопировать тот же манифест в `update/latest.json`, закоммитить и отправить в main. Иначе приложение может увидеть обновление до появления APK.
4. Обновить сведения о текущей версии в README.
5. Проверить основной адрес:

   ```bash
   curl -fL https://github.com/Strokln/Stroka/releases/latest/download/update.json
   ```

6. При необходимости обновить кеш зеркала:

   ```bash
   curl -f https://purge.jsdelivr.net/gh/Strokln/Stroka@main/update/latest.json
   ```

7. На телефоне с предыдущей версией выполнить **Настройки → О приложении → Проверить обновления**, затем проверить загрузку, проверку подписи и установку с сохранением данных.

## Проверки и ограничения

- Автоматическая проверка выполняется при запуске не чаще раза в сутки. Ручная доступна в настройках. Автообновление не означает скрытую установку: Android запрашивает подтверждение пользователя.
- Приложение проверяет SHA-256 файла, packageName, versionCode и сертификат подписи. Неподходящий файл отклоняется.
- Обновление должно иметь больший versionCode и ту же подпись. Не отключайте эти проверки.
- Описания изменений поддерживают `ru`, `en` и другие языковые ключи.
- Для отмены предложения обновления нужно вернуть манифест предыдущей версии в оба источника. Уже установленные версии не понижаются.
- Версии до 0.3.8-ru.1 используют канал автора: для перехода на собственный канал нужно один раз установить 0.3.8-ru.1 вручную.
